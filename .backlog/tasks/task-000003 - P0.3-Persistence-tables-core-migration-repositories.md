## Implementation Plan

<!-- SECTION:PLAN:BEGIN -->
1. persistence/tables.py: typed SQLAlchemy 2.0 ORM rows on persistence.base.Base for the 8 tables in PLAN.md 4.2 (workspaces, search_queries, sources, source_links, chunks, claims, highlights, trace_events). UUID string PKs (trace_events: INTEGER autoincrement, sqlite_autoincrement so SSE cursors never reuse IDs). Enums stored as their string values. UTC-aware timestamps via a small TypeDecorator. Every non-workspace table has workspace_id FK (ON DELETE CASCADE) + index. Explicitly named constraints: UNIQUE(workspace_id, external_id) on sources, UNIQUE(from_source_id, to_source_id, kind) on source_links.
2. migrations/versions/0002_core_schema.py (down_revision 0001_empty_baseline): op.create_table for each table matching tables.py; downgrade drops them in reverse FK order.
3. persistence/repositories.py: create_session_factory(engine) (expire_on_commit=False) and a Repositories class over an async_sessionmaker (one short transaction per call, safe for concurrent stage work). Helpers: create/get/list/update per table, update_source_fields(id, **fields), list_sources(ws, statuses), append_event, events_after(ws, last_id) returning models.events.TraceEvent. *_json fields accept Pydantic models or plain JSON values and are serialized; unknown field names raise.
4. data/: replace data/seeds/.gitkeep with data/workspaces/.gitkeep, update data/.gitignore so only those two files are tracked.
5. Tests (tests/integration/persistence/): update the migration test to expect the new tables on upgrade, none after downgrade, and no drift between the migration and tables.py; one test that a duplicate (workspace_id, external_id) source insert is rejected.
6. Verify: uv run alembic upgrade head on a fresh DB, ruff format/check, mypy, pytest, uv build.
<!-- SECTION:PLAN:END -->
